API 文档 ClawBridge HTTP API

ClawBridge HTTP API 文档

ClawBridge 提供扫码绑定、管理后台与对外消息推送 API。所有 API（静态页面与二维码 SVG 除外）返回 JSON； 时间字段统一为 Unix 毫秒整数；写接口接受 Content-Type: application/json。

当前基线：ClawBridge 1.0.0（数据库 schema v1）。本文档只描述 HTTP API 契约； 控制台交互说明以管理后台为准。批量推送、用户凭据、规则与定时通知的接口与模板语法见对应章节。

概览

ClawBridge 是一个多用户微信 ClawBot 消息推送平台：用户通过公开绑定页扫码绑定微信后， 外部系统即可使用 API Key 通过推送 API 向指定用户或全体已绑定用户发送消息。

统一错误格式

所有错误响应体均为：

{ "error": { "code": "BAD_REQUEST", "message": "人类可读的错误信息" } }

两类鉴权

推送 API 使用数据库管理的 API Token（Authorization: Bearer 或 X-Api-Key）；管理后台 API 使用登录 Cookie cb_session （HttpOnly，12 小时有效）。

异步投递

发消息接口只负责入队并返回 202 Accepted，由服务端按账号限流异步投递； 可通过查询接口获得最终投递状态。

鉴权与 API Key

推送 API 的 API Key 由数据库管理（AES 加密保存），首次启动自动生成并写入数据目录的 api-token.txt（Docker 默认挂载在 /app/data）；管理员可在后台「运行配置 → 安全」重新生成/重置， 无需再设置环境变量 API_TOKEN。 关闭「推送 API」开关后接口整体不可用。

请求时使用以下任一请求头：

  • Authorization: Bearer <API_TOKEN>
  • X-Api-Key: <API_TOKEN>

推送 API 按 API Key 限流（默认 60 次/分钟）；单条文本默认上限 4000 字符；to 数组支持 1–100 个用户 ID。

推送 API

Webhook 兼容入口

POST /api/v1/webhook 
curl -X POST "http://localhost:10380/api/v1/webhook?token=$API_TOKEN&to=u_abc" \
  -H "Content-Type: application/json" \
  -d '{"text":"Webhook 消息"}'

目标可用 query ?to= / ?groupId= / ?broadcast=1， 也可放在 JSON body。支持 JSON、纯文本、application/x-www-form-urlencoded； 文本优先取 text/content/message/msg，否则回退整个 JSON。响应 202。

给指定用户发消息

POST /api/v1/messages 
curl -X POST http://localhost:10380/api/v1/messages \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"to":["u_abc","u_def"],"text":"您的订单已发货"}'

请求体：

{
  "to": ["u_abc", "u_def"],   // 用户 id 数组（1..100）
  "text": "您的订单已发货"
}

响应 202：

{
  "accepted": 2,
  "queued": [
    { "outboxId": "ob_1", "userId": "u_abc", "status": "queued" },
    { "outboxId": "ob_2", "userId": "u_def", "status": "queued" }
  ]
}

未知或未绑定用户会返回 404，并在响应中列出 unknownUserIds；全部用户无效时不入队。

广播

POST /api/v1/broadcast 
curl -X POST http://localhost:10380/api/v1/broadcast \
  -H "X-Api-Key: $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text":"系统维护通知"}'

请求体 { "text": "系统维护通知", "onlyBound": true }；响应 202：

{ "accepted": 3, "queued": [ { "outboxId": "ob_1", "userId": "u_abc", "status": "queued" } ] }

查询投递状态

GET /api/v1/messages/{outboxId} 
curl http://localhost:10380/api/v1/messages/ob_1 -H "Authorization: Bearer $API_TOKEN"

{
  "id": "ob_1",
  "userId": "u_abc",
  "status": "queued|sending|sent|failed",
  "attempts": 1,
  "error": "",
  "serverMessageId": "…",
  "createdAt": 1760000000000,
  "sentAt": 1760000001000
}

用户列表（供外部系统发现收件人）

GET /api/v1/users?status=active&limit=100 
{
  "items": [
    { "id": "u_abc", "displayName": "张三", "status": "active",
      "boundAt": 1760000000000, "hasContextToken": true }
  ]
}

多媒体上传与发送

ClawBridge 支持发送图片、视频与普通文件，并可从微信接收图片/文件/视频/语音附件。 出站媒体采用「原始二进制上传 + mediaId 引用」的方式，不新增 multipart 依赖。

方向 支持类型 说明
出站（发送） 图片 image/*、视频 video/*、普通文件（pdf/zip/docx…） 可附带文字 caption（先发文字再发媒体）；按 MIME 自动路由
入站（接收） 图片、文件、视频、语音 服务端自动从微信 CDN 下载并解密落盘，管理后台可预览/下载
出站语音 暂不支持 需要 SILK 转码依赖，接口返回 400 并说明原因

1. 管理后台上传媒体（原始二进制）

POST /api/admin/media

请求体为文件原始二进制（非 multipart），Content-Type 使用文件 MIME；原始文件名通过 X-File-Name 传递 （需 encodeURIComponent 编码），并带 CSRF 头 X-Requested-With: ClawBridge-Admin。 

curl -X POST http://localhost:10380/api/admin/media \
  -b "cb_session=…" \
  -H "X-Requested-With: ClawBridge-Admin" \
  -H "Content-Type: image/png" \
  -H "X-File-Name: %E5%9B%BE%E7%89%87.png" \
  --data-binary @./图片.png

响应 201：

{
  "media": { "id": "att_…", "kind": "image", "mime": "image/png",
             "fileName": "图片.png", "size": 12345,
             "url": "/api/admin/media/att_…" },
  "limits": { "maxBytes": 26214400, "allowedImage": ["image/jpeg", "image/png"] }
}

单文件上限 MEDIA_MAX_BYTES（默认 25MB），超过返回 413；缺少文件名或类型不支持返回 400；未登录返回 401。

2. 发送带媒体的消息

先上传拿到 mediaId，再在发送接口请求体中引用： text 与 mediaId 至少传一个； 有媒体时 text 作为 caption 先发送。 

# 管理后台：给指定用户发送图片
curl -X POST http://localhost:10380/api/admin/users/u_abc/messages \
  -b "cb_session=…" \
  -H "X-Requested-With: ClawBridge-Admin" \
  -H "Content-Type: application/json" \
  -d '{"text":"看图","mediaId":"att_…"}'

# 对外推送 API（API Key）：同样支持 mediaId，可对多个 to 共用同一个 mediaId
curl -X POST http://localhost:10380/api/v1/messages \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"to":["u_abc"],"text":"报告","mediaId":"att_…"}'

响应 202 的 queued 项会附带媒体摘要 （media.id / kind / fileName / size / url）。 广播接口仍只支持文本。

3. 对外 API 上传媒体

POST /api/v1/media 
curl -X POST http://localhost:10380/api/v1/media \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: video/mp4" \
  -H "X-File-Name: demo.mp4" \
  --data-binary @./demo.mp4

4. 读取 / 下载媒体

GET /api/admin/media/{attId}
GET /api/v1/media/{attId}

管理后台接口使用 Cookie 鉴权，可直接用于 <img> / <video> 的 src（同源）； v1 接口使用 API Key 鉴权。默认图片/视频 inline， 其他文件 attachment；加 ?download=1 强制下载。响应支持 Range 请求（视频可拖动进度条）。

5. 限制与出站行为

  • 出站单文件上限 MEDIA_MAX_BYTES = 25MB；入站单文件上限 INBOUND_MEDIA_MAX_BYTES = 100MB。
  • 图片/视频 MIME 白名单由 MEDIA_ALLOWED_IMAGE_MIME / MEDIA_ALLOWED_VIDEO_MIME 配置，未命中的按普通文件发送。
  • 一条带 caption 的媒体消息在服务端会拆成 最多 2 次 sendmessage（文字 + 媒体），每次都会消耗该账号的发送限流令牌。
  • 媒体发送失败会按重试策略重新上传；附件文件缺失时该条消息直接标记 failed。

绑定状态机

绑定页轮询 GET /api/bind/sessions/{sessionId}?token=… 获取 status 字段，可能取值如下：

status 说明 前端行为
waiting 等待扫码 展示二维码，继续轮询
scanned 已扫码，等待手机确认 提示「已扫码，请在手机上确认」
need_verifycode 需要输入手机微信上显示的配对数字 展示数字输入框，提交 verify-code
refreshing 二维码过期，正在自动刷新（最多 3 次） 提示正在刷新，等待新二维码
verify_blocked 配对数字错误次数过多，正在刷新二维码 提示刷新，等待重新扫码
confirmed 绑定成功，返回 user 字段 展示绑定成功与用户信息
already_bound 该微信已绑定过本服务（binded_redirect），user 可能返回已有用户 提示已绑定，无需重复绑定
expired / timeout / cancelled 会话结束，需重新创建 展示原因并提供「重新生成二维码」
error 协议/网络错误导致失败，error 字段给出原因 展示错误原因，可重试

绑定会话有效期默认 10 分钟；confirmed 后会话仍可查询，保留 10 分钟。

管理后台 API

登录成功后服务端通过 Set-Cookie 下发 HttpOnly Cookie cb_session（SameSite=Lax，默认 12 小时有效），后续请求自动携带。 所有写接口（POST/DELETE）必须带 X-Requested-With: ClawBridge-Admin。 

# 登录
curl -i -X POST http://localhost:10380/api/admin/login \
  -H "Content-Type: application/json" \
  -d '{"password":"你的管理密码"}'

# 登录后携带 Cookie 查询概览
curl http://localhost:10380/api/admin/overview -b "cb_session=…"

# 给用户发消息（写接口需要 CSRF 头）
curl -X POST http://localhost:10380/api/admin/users/u_abc/messages \
  -H "Content-Type: application/json" \
  -H "X-Requested-With: ClawBridge-Admin" \
  -b "cb_session=…" \
  -d '{"text":"你好"}'

常用查询参数： GET /api/admin/users?status=active|unbound|paused|all&q=&limit=50&offset=0； GET /api/admin/messages?direction=inbound|outbound|all&status=&limit=50&offset=0&userId=。

用户凭据（User Secrets）

用户凭据用于保存「每个用户自己的第三方系统密钥」，供规则/定时通知的请求模板按用户注入。 一条凭据可包含多个字段（例如 gps 凭据含 token 与 deviceId 两个字段）。 所有字段值以 AES-256-GCM（由 APP_SECRET 派生密钥）加密落库； 接口只写不读：任何读取响应都不会返回明文，只返回字段名与掩码 hints（如 ••••ab12）。

GET /api/admin/users/{id}/secrets （Cookie）
PUT /api/admin/users/{id}/secrets/{name} （Cookie + CSRF）
DELETE /api/admin/users/{id}/secrets/{name} （Cookie + CSRF；成功 204，不存在 404）

1. 列表（不返回明文）

curl http://localhost:10380/api/admin/users/u_abc/secrets \
  -b "cb_session=…"
# → 200 {
#   "items": [
#     { "name": "gps", "label": "GPS 平台",
#       "fieldNames": ["token", "deviceId"],
#       "hints": { "token": "••••ab12", "deviceId": "••••9f3c" },
#       "createdAt": 1760000000000, "updatedAt": 1760000000000, "lastUsedAt": 0 }
#   ]
# }

字段：name（凭据名）、label（备注，可为空）、 fieldNames（字段名数组）、hints （字段名 → 掩码串）、createdAt/updatedAt/ lastUsedAt（最近一次被规则/定时任务解析使用的时间，0 表示未使用）。

2. 新建 / 全量更新

curl -X PUT http://localhost:10380/api/admin/users/u_abc/secrets/gps \
  -b "cb_session=…" \
  -H "X-Requested-With: ClawBridge-Admin" \
  -H "Content-Type: application/json" \
  -d '{"label":"GPS 平台","fields":{"token":"sk_live_xxx","deviceId":"dev_123"}}'
# → 200 { "item": { "name":"gps", "label":"GPS 平台",
#                    "fieldNames":["token","deviceId"], "hints":{...},
#                    "createdAt":..., "updatedAt":..., "lastUsedAt":0 } }
# 响应同样不含任何字段明文；再次 PUT 同名凭据 = 全量替换字段。

fields 必须是 {"字段名":"字符串值"} 对象， 至少 1 个、最多 20 个字段；字段值长度为 1..4096 字符； 凭据名 [A-Za-z0-9_-]{1,32}、字段名 [A-Za-z0-9_.-]{1,32}、label ≤ 200 字符；字段 JSON 总大小 ≤ 32KB。非法输入返回 400 BAD_REQUEST；用户不存在返回 404。

3. 删除

curl -X DELETE http://localhost:10380/api/admin/users/u_abc/secrets/gps \

入站消息 API

拉取式 REST 接口：获取微信用户发给 ClawBot 的入站消息（含附件元数据），支持 since / cursor 增量拉取与 wait 长轮询，便于外部系统集成。

GET /api/v1/inbound/messages

鉴权：Authorization: Bearer <API_TOKEN> 或 X-Api-Key。查询参数：

参数 说明
limit1–200，默认 50
since毫秒时间戳（可选，独占：只返回 receivedAt > since 的消息）
cursor不透明游标（可选，优先于 since；来自上次响应的 nextCursor）
userId可选，只看某用户
groupId可选，只看某分组内用户的消息（按用户当前分组归属）
wait0–30 秒（可选，长轮询：无新消息时最多等待 N 秒，收到新消息立即返回）

响应 200（按 (receivedAt, id) 升序）：

{
  "items": [ {
    "id": "in_…",
    "userId": "u_…",
    "displayName": "张三",
    "groups": [ { "id": "grp_…", "name": "VIP客户", "color": "#07C160" } ],
    "text": "你好（媒体消息为 [图片]/[视频]/[文件]/[语音] 占位）",
    "itemTypes": "1",
    "createdAt": 1760000000000,
    "receivedAt": 1760000000123,
    "attachments": [ {
      "id": "att_…", "kind": "image", "mime": "image/jpeg",
      "fileName": "", "size": 448642, "status": "ready",
      "url": "/api/v1/media/att_…",
      "downloadUrl": "/api/v1/media/att_…?download=1"
    } ]
  } ],
  "nextCursor": "eyJ0IjoxNzYwMDAwMDAxMjMsImlkIjoiaW5fLi4uIn0",
  "hasMore": false,
  "serverTime": 1760000002000
}
  • cursor 编码为 base64url JSON：{ "t": receivedAt, "id": "in_…" }，服务端按字典序稳定翻页（同毫秒多条不会重复/遗漏）。
  • nextCursor：还有更多数据时返回最后一条的游标；无数据时可能为 null。下次请求优先使用它。
  • wait > 0 且无新消息时，服务端每 500ms 重新查询，直到有新消息或超时；超时返回 items=[] 与传入的游标。
  • 附件只返回元数据，文件内容通过 GET /api/v1/media/{attId} 读取（API Key 鉴权，支持 Range）。
  • 鉴权失败 401；参数非法（limit/wait 越界、cursor 格式错误、since 非数字）返回 400。

轮询示例（首次 + 增量长轮询）

# 1) 首次拉取最近 50 条（升序）
curl -s "http://localhost:10380/api/v1/inbound/messages?limit=50" \
  -H "Authorization: Bearer $API_TOKEN"

# 2) 用 nextCursor 增量拉取；无新消息时长轮询最多 25 秒
NEXT=$(curl -s "http://localhost:10380/api/v1/inbound/messages?limit=50" \
  -H "Authorization: Bearer $API_TOKEN" | jq -r '.nextCursor // empty')
curl -s "http://localhost:10380/api/v1/inbound/messages?limit=50&cursor=$NEXT&wait=25" \
  -H "Authorization: Bearer $API_TOKEN"
# 持续轮询（bash + jq）
NEXT=""
while true; do
  URL="http://localhost:10380/api/v1/inbound/messages?limit=50&wait=25"
  [ -n "$NEXT" ] && URL="$URL&cursor=$NEXT"
  RESP=$(curl -s "$URL" -H "Authorization: Bearer $API_TOKEN")
  echo "$RESP" | jq -c '.items[] | {id, userId, displayName, text, receivedAt}'
  NEXT=$(echo "$RESP" | jq -r '.nextCursor // empty')
done

管理后台消息记录也支持按分组筛选（GET /api/admin/messages?groupId=…）， 并在用户行与消息行展示分组徽章。

消息保活（24h 会话保活）

微信 ClawBot 的主动下发依赖「用户最近一次主动消息」形成的约 24 小时会话窗口。 对开启保活的用户，ClawBridge 会在其最后一条入站消息满 12 小时后 首次提醒，之后每 6 小时重复提醒，直到用户回复刷新会话窗口或窗口过期。

  • opt-in：默认关闭；管理员可对单个用户或整个分组批量开启/关闭。
  • 未回复时重复提醒：首次提醒后记录 keepaliveLastSentAt；距上次提醒满 repeatMs （默认 6h）且窗口未过期时再次提醒；用户回复消息后窗口重新计时。
  • 仅在窗口仍然有效时发送（剩余时间 > 0）；窗口已过期或从未有过入站消息的用户不会发送。
  • 保活消息走现有 outbox 队列（source=keepalive），受每账号发送限流、 -2/-14 处理等与普通消息完全一致。
  • 触发条件：用户 active、已开启保活、lastInboundAt > 0、未冷却、 now - lastInboundAt ∈ [window - lead, window)， 且本窗口未发过或距上次提醒满 repeatMs。

1. 单用户开关（管理后台）

PATCH /api/admin/users/{id}/keepalive 
curl -X PATCH http://localhost:10380/api/admin/users/u_xxxxxxxx/keepalive \
  -b "cb_session=…" \
  -H "X-Requested-With: ClawBridge-Admin" \
  -H "Content-Type: application/json" \
  -d '{"enabled":true}'
# → 200 { "user": { ..., "keepaliveEnabled": true, "keepaliveLastSentAt": 0 } }

2. 分组批量开关

POST /api/admin/groups/{id}/keepalive 
curl -X POST http://localhost:10380/api/admin/groups/grp_xxxxxxxx/keepalive \
  -b "cb_session=…" \
  -H "X-Requested-With: ClawBridge-Admin" \
  -H "Content-Type: application/json" \
  -d '{"enabled":true}'
# → 200 { "updated": 3, "group": { ...GroupView } }

错误：用户/分组不存在返回 404；enabled 非 boolean 返回 400；其余沿用统一错误格式。

3. 相关数据字段

  • GET /api/admin/users：UserView 增加 keepaliveEnabled（boolean）与 keepaliveLastSentAt（毫秒，0 表示从未发送）。
  • GET /api/admin/config：新增 keepalive: { enabled, windowMs, leadMs, tickMs, maxPerTick, text }。
  • GET /api/admin/overview：stats 新增 keepaliveEnabledUsers 与 keepaliveSent24h。

规则列表（关键词触发 → 外部 HTTP 接口 / 默认文本回复）

当指定范围的微信用户发来包含关键词的消息时，ClawBridge 可调用配置的 外部 HTTP 接口，把消息中的参数传给接口，解析接口返回并自动回复给该用户； 也可以选择不请求外部接口，直接回复一段默认文本。 规则默认不启用，由管理员在后台按需创建与开启。

1. 处理流程

入站消息（仅文本）→ 规则引擎（异步队列，不阻塞 getupdates）
  → 规则启用？触发范围命中（all / users / groups）？
  → 关键词 / 正则命中？同消息+规则未重复？
  → 按 priority（数字越小越先）+ created_at 取第一条命中规则（一消息最多执行一条）
  → request.mode=none？→ 直接使用默认回复文本
  → 否则：参数提取 → 渲染请求模板 → 调用外部 HTTP（SSRF 防护 / 超时 / 响应大小限制）
  → 解析响应（JSON 点路径或纯文本）→ 渲染回复模板（或兜底文案）
  → 写 app_rule_logs（脱敏预览）
  → 入队 outbox（source='rule'）→ 微信回复用户（复用限流 / -2 / -14 / context_token）

2. 触发范围与匹配

  • scope_type：all（全部用户）/ users（指定用户，scope_ids 为用户 id）/ groups（指定分组，用户属于任一分组即命中）。
  • match_mode： contains（消息包含任一关键词，大小写不敏感）、 equals（trim 后全等任一关键词）、 regex（regex_pattern，u flag，保存时校验合法性）。
  • 关键词 keywords：1–10 个、每个 1–50 字；正则模式忽略关键词。
  • 一消息命中多条规则时，按 priority 升序、同优先级按创建时间取第一条。

3. 参数提取

extraction_mode extraction_config 说明
none{}不提取：消息中不需要参数，直接按模板调用接口（仍可使用内置变量）；不检查缺参
multi{"extractors":[...],"required":["city","date"]}多参数组合提取（唯一提取模式）：按顺序执行多个提取项（trailing/regex/json/fulltext）并合并参数；required 中的参数缺失视为缺参

后台「提取模式」只有 不提取 / 多参数组合提取 两种。

内置变量：{text}（消息原文）、{arg} （组合提取中 trailing/fulltext 的主参数）、{userId}、{name} （微信显示名）、{now}（毫秒时间戳）。 必需参数为空时不调用外部接口，直接回复 fallback_text（若配置）， 日志记为 failed（error=missing params）。

3.1 不请求模式（关键词直接回复默认文本）

  • 规则请求体使用 "request":{"mode":"none"}；此时 request.url 为空，不提取参数、不访问外部接口。
  • 命中关键词/正则后，直接使用 response.template 作为回复文本； 模板为空时使用 response.fallbackText；两者都为空会返回 400。
  • 运行日志仍记录 source='rule' 回复入队，httpStatus=null。
  • 示例："request":{"mode":"none"} + "response":{"type":"text","template":"收到，我们会尽快处理。"}

4. 请求模板与安全（SSRF）

  • 请求方法 GET / POST；URL、Header 值、Body 支持 {变量} 占位（URL 中的变量做 URL 编码，Header/Body 原文替换并限制长度）。
  • request_body_template 仅 POST 使用；GET 忽略 body。
  • Header 通过 requestHeaders 对象传入并加密落库； 读取接口只返回 headerNames（键名列表），不返回值。 更新时传 requestHeaders 即全量替换（{} 清空），不传则保持不变。
  • SSRF 防护：仅允许 http/https、禁止 URL 携带 userinfo； 默认拒绝私网/环回/链路本地/组播/保留地址；域名会先解析 IP 再判断； APP_RULES_ALLOWED_HOSTS 白名单中的主机允许访问内网； 重定向最多 3 跳且每跳重新校验；超时取 min(timeout_ms, APP_RULE_TIMEOUT_MS)；响应体超过 APP_RULE_MAX_RESPONSE_BYTES 判失败；失败不重试（避免重复副作用）。
  • 日志/接口响应不记录完整 Header 值或敏感请求体，预览做脱敏与截断。

4.1 用户凭据占位符（{credential:名称.字段}）

  • 请求 URL / Header 值 / Body 模板除内置变量外，还支持 {credential:名称.字段}：按触发该条消息的用户 解析其用户凭据（需先在后台为该用户创建凭据，见 用户凭据）。 凭据名/字段名规则与凭据接口一致（[A-Za-z0-9_-]{1,32} / [A-Za-z0-9_.-]{1,32}）。
  • 替换发生在服务端执行时：URL 中的凭据值做 URL 编码，Header/Body 原文替换并限制长度； 凭据值只在进程内使用，不回显给任何读取接口。
  • 凭据/字段缺失或无法解密：本次不调用外部接口，按规则失败处理 （运行日志 status=failed，error 只含凭据名/字段名、不含值）；若配置了兜底文案则按失败兜底发送。
  • 日志、requestPreview、错误信息等所有落库/返回内容在写入前， 把本次使用的凭据值替换为 ***（含 URL 编码形式），只记录凭据名。
  • 示例：{credential:gps.token}、 {"Authorization":"Bearer {credential:gps.token}"}、 {"deviceId":"{credential:gps.deviceId}"}。

5. 响应解析与回复

  • response_type=json：按 response_path （点路径，如 data.answer、a.b.0.c）取值； 路径为空时优先取 reply 字段，否则对整个对象 JSON.stringify。
  • response_type=text：直接使用响应文本（trim、截断）。
  • 模板根：response_path 选中节点后，模板根即该节点， 模板不用重复路径；路径为空时才是完整响应对象（如路径=data.list 时写 {{count .}}/{{#each .}}）； 模板只按模板根/当前循环上下文查找路径；需要完整响应根时用 {{@responseRoot.字段}}。
  • 回复模板 reply_template：按 Markdown 发送，支持 {{路径}}（如 {{data.answer}}）；{{reply}} 表示模板根/响应对象的 reply 字段（空路径时解析器会优先使用它）；内置 {{response}} （解析后的文本）与 {{raw}}（原始响应文本）；为空时直接使用解析结果。
  • 列表渲染：{{count data.list}} 输出数量； {{#each data.list}} … {{/each}} 逐项渲染（内层 {{字段}}、{{@index}} 从 0、 {{@number}} 从 1；空列表分支可写 {{#each 路径}}...{{else}}暂无数据{{/each}}； each 可嵌套多层，内层用 {{../字段}}、{{../@index}}、{{@root.字段}}/{{@responseRoot.字段}}（@root=模板根，@responseRoot=完整响应根，可访问 rows 的兄弟字段）。示例：
  • 条件判断与默认值：支持 {{#if 条件}}...{{else if 条件}}...{{else}}...{{/if}}、 {{#unless 条件}}...{{/unless}}； 条件支持真值判断及 = / != / > / >= / < / <= 比较， 左侧可为字段或 count 路径；支持 not 条件、条件A and 条件B、 条件A or 条件B（引号内不拆分）； {{default 路径 "兜底文案"}} 在值为空时输出兜底文案。 规则/定时编辑弹窗中的「预览模板」可粘贴示例响应离线预览，不访问外部接口。
  • {{noreply}}：模板渲染结果包含该指令时不回复（也不使用兜底文案； 运行日志仍记录本次执行）。
【天气概览】{{count data.data}} 个城市
{{#each data.data where weather=雨}}{{@number}}. {{city}}：有雨 {{temperature}}℃
{{/each}}【晴天城市】{{count data.data where weather=晴}} 个
{{#each data.data where weather=晴}}{{@number}}. {{city}}：晴 {{temperature}}℃
{{/each}}
  • 空回复或接口失败时使用 fallback_text；回复文本按 MAX_TEXT_LENGTH（默认 4000）截断； 最终入队 outbox，source='rule'。

6. 限流与去重

  • 同一入站消息对同一规则最多执行一次（数据库唯一索引，getupdates 重放安全）。
  • 规则自身不再设置冷却或每小时限额；调用频率统一由微信账号默认发送限流控制（默认 7 条 / 5 分钟 / 账号，由 RATE_LIMIT_MAX=7 / RATE_LIMIT_WINDOW_MS=300000 控制）。日志仅保留同消息+规则去重。
  • 执行并发 APP_RULES_WORKER_CONCURRENCY；队列上限 APP_RULE_MAX_QUEUE（满则丢弃并 warn 日志）。

定时通知（Scheduled Notifications）

定时通知按时间计划主动调用外部 HTTP 接口，把解析结果通过微信推送给指定用户或指定分组， 无需用户先发消息；它属于「接口应用」的时间计划模式，与关键词触发（收到消息才触发）共用请求/响应/模板能力。

1. 处理流程

调度器每 SCHEDULER_TICK_MS（默认 15s）扫描到期任务（enabled=1 AND next_run_at<=now）
  → 目标用户 = 指定用户 / 指定分组内 active 用户 / 全部 active 用户（去重）
  → 汇总模式（perUserMode=false）：
      渲染一次请求模板（URL/Header/Body，内置变量 {now}/{date}/{time}/{taskName}）
      → 调用外部 HTTP（SSRF 防护 / 超时 / 响应大小限制 / 重定向复验）
      → 解析响应 → 渲染一份通知文本（{{path}}/{{response}}/{{raw}}）→ 发给全部目标
  → 按用户模式（perUserMode=true）：
      逐目标用户解析 {credential:名称.字段} → 相同凭据值合并请求
      → 按用户渲染通知（额外可用 {{userId}}/{{userName}}）→ 缺凭据跳过该用户
  → 逐个入队 outbox（source=schedule）→ 复用现有微信发送限流
  → 写 scheduled_task_logs（状态 success/failed/skipped/partial、HTTP/耗时/错误/预览/收件人数）
  → 更新 last_run_at / last_status / next_run_at

任务停用后不再自动执行；SCHEDULER_ENABLED=false 时调度器不启动 （后台仍可管理任务、测试运行与立即执行）。单实例调度（与保活一致）。

2. 计划（schedule）

  • interval（间隔）：interval_ms 范围 60000..2592000000（1 分钟–30 天）；可选每日生效时间段 windowStart/windowEnd（HH:mm，成对、支持跨午夜；区间为 [开始, 结束]，结束分钟也触发，窗口外自动推进）； 首次创建时 next_run_at = now + interval_ms， 执行后按本次执行开始时间 + 间隔计算下一次。
  • daily（每日定时）：daily_time 为 HH:mm， 按 SCHEDULER_TIMEZONE（默认 Asia/Shanghai）执行； 当前时间已过当天 HH:mm 则排到明天。
  • 服务重启：过期 ≤5 分钟的 interval 任务补跑一次，超过则顺延下一周期； daily 任务过期时启动后立即补跑一次，避免漏发。
  • 每 tick 最多取 10 个到期任务、按 next_run_at 升序；单任务失败不影响其他任务。

3. 请求模板与安全（SSRF）

  • 请求方法 GET / POST； URL、Header 值、Body 支持内置变量 {now}、 {date}、{time}、 {taskName}。
  • Header 通过 request.headers 对象传入并加密落库； 读取接口只返回 headerNames（名称列表），值显示为 ••••••。 更新时不传=保持不变、传 {} 清空、传对象=全量替换。
  • 复用接口应用的 SSRF 防护：仅 http/https、禁止 userinfo、默认拒绝私网/环回/链路本地地址， 域名先解析 IP 再判断；APP_RULES_ALLOWED_HOSTS 白名单可放行内网； 重定向最多 3 跳且每跳复验；超时取 min(task.timeoutMs, SCHEDULER_TIMEOUT_MS)； 响应体超过 APP_RULE_MAX_RESPONSE_BYTES 判失败，失败不重试。

4. 响应解析与通知模板

  • response.type=json：按 response.path （点路径，可含数组下标）取值；路径为空时优先取 reply 字段，否则整个对象 JSON 化。
  • response.type=text：直接使用响应文本（trim、截断）。
  • 模板根：response.path 选中节点后，模板根即该节点， 模板不用重复路径；路径为空时才是完整响应对象（如路径=data.list 时写 {{count .}}/{{#each .}}）； 模板只按模板根/当前循环上下文查找路径；需要完整响应根时用 {{@responseRoot.字段}}。
  • 通知模板 reply_template：按 Markdown 发送，支持 {{path}}（如 {{data.weather}}）、 {{response}}（解析后的文本）、 {{raw}}（原始响应文本）；列表支持 {{count data.list}} 与 {{#each data.list}}{{字段}}{{/each}}（@index/@number；each 可嵌套多层，内层用 {{../字段}}、{{../@index}}、{{@root.字段}}/{{@responseRoot.字段}}（@root=模板根，@responseRoot=完整响应根，可访问 rows 的兄弟字段）。示例：
  • 条件判断与默认值：支持 {{#if 条件}}...{{else if 条件}}...{{else}}...{{/if}}、 {{#unless 条件}}...{{/unless}}； 条件支持真值判断及 = / != / > / >= / < / <= 比较， 左侧可为字段或 count 路径；支持 not 条件、条件A and 条件B、 条件A or 条件B（引号内不拆分）； {{default 路径 "兜底文案"}} 在值为空时输出兜底文案。 规则/定时编辑弹窗中的「预览模板」可粘贴示例响应离线预览，不访问外部接口。
  • {{noreply}}：模板渲染结果包含该指令时不回复（也不使用兜底文案； 运行日志仍记录本次执行）。
【天气概览】{{count data.data}} 个城市
{{#each data.data where weather=雨}}{{@number}}. {{city}}：有雨 {{temperature}}℃
{{/each}}【晴天城市】{{count data.data where weather=晴}} 个
{{#each data.data where weather=晴}}{{@number}}. {{city}}：晴 {{temperature}}℃
{{/each}}
  • 接口失败 / 超时 / JSON 解析失败 / 模板为空：若配置了 fallback_text 则把兜底文案发送给全部目标；否则本次不发送（failed 日志）。
  • 目标：targets.type=all 为全部 active 用户； targets.type=users 为指定用户 id， targets.type=groups 为指定分组 id（分组内 active 用户去重）， 上限 SCHEDULER_MAX_RECIPIENTS（默认 200，按用户 id 稳定排序截断）。

5. 按用户模式（perUserMode）

默认（perUserMode=false，汇总模式）只渲染一次请求、解析一次结果， 把同一份通知发给全部目标用户。开启按用户模式后，ClawBridge 会为每个目标用户 用其自己的凭据分别渲染请求、调用接口并发送通知，适用于「每个用户调用各自第三方账号」的场景。

  • 开关字段：TaskView 与创建/更新请求体中的 perUserMode （布尔，默认 false）。仅按用户模式允许请求模板（URL/Header/Body）中出现 {credential:名称.字段}；汇总模式下保存含凭据占位符的模板返回 400 BAD_REQUEST。
  • 目标展开：targets 展开为具体 active 用户并去重， 最多 scheduler.perUserMaxRecipients（默认 50，范围 1–200， 后台「运行配置 → 定时通知」可改；属重启生效配置），超出部分按用户 id 稳定排序截断。
  • 请求合并：凭据字段值完全相同的用户按「凭据值指纹」合并为同一次外部请求， 避免对同一第三方账号重复调用；请求模板与通知文本均可按每个用户单独渲染， 模板上下文额外提供 {{userId}} 与 {{userName}}（可用于 URL/Header/Body/通知模板）。
  • 并发与超时：单任务按用户请求并发受 scheduler.perUserConcurrency（默认 2，范围 1–10，后台可改）限制； 单次请求超时取 min(task.timeoutMs, SCHEDULER_TIMEOUT_MS)； 单任务总超时 30s；任务执行有互斥锁，避免同一任务重入。
  • 缺凭据：某用户缺少模板引用的凭据/字段时，跳过该用户并记录事件 （如 scheduled_recipient_skipped，仅 userId/凭据名/字段名，不含值）， 不发兜底、不影响其他用户；单用户请求或入队失败只影响该用户 （如 scheduled_recipient_failed，兜底文案按配置处理）。
  • 整体状态：全部用户成功 = success； 部分用户被跳过或失败 = partial（后台日志显示「部分成功」）； 全部失败 = failed。运行日志 scheduled_task_logs.status 允许 success / failed / skipped / partial，列表与日志接口的 status 过滤接受这四个值。
  • 示例片段： "perUserMode": true， "request": {"url": "https://api.example.com/gps?token={credential:gps.token}"}， "response": {"template": "{{userName}}：今日位置 {{location}}"}。

错误码

HTTP 状态码与业务错误码一一对应，响应体形如 { "error": { "code": "…", "message": "…" } }：

HTTP code 含义
400BAD_REQUEST参数错误（如文本为空或超长、配对码格式错误）
401UNAUTHORIZED未登录、Cookie 过期或 API Key 错误
403FORBIDDEN无权限执行该操作（如缺少 CSRF 请求头）
404NOT_FOUND资源不存在；推送 API 会同时返回 unknownUserIds
409CONFLICT状态冲突（用户未绑定、冷却中，或绑定会话状态不允许提交配对码）
429RATE_LIMITED触发限流（绑定创建 / 登录 / 推送 API / 账号发送）
500INTERNAL服务器内部错误
503UNAVAILABLE依赖服务不可用（如无法连接微信 API，创建绑定会话时 code 为 SERVICE_UNAVAILABLE）
