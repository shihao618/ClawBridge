# 微信 Markdown 兼容规则（后台模板 / 预览 / 发送）

> 目标：后台「回复模板 / 定时通知模板」里写的 Markdown，**发送到微信 ClawBot 后的效果 = 后台 Markdown 预览**。
> 本文说明微信实际渲染哪些语法、ClawBridge 在发送前做什么处理，以及预览为何与发送一致。

## 1. 权威依据

微信 iLink Bot 通道的文本始终是「纯文本 + 客户端就地渲染部分 Markdown」。腾讯官方微信插件
`@tencent-weixin/openclaw-weixin`（MIT，ClawBridge 的协议与行为参考版本 `2.4.10`）在所有**出站文本**上
应用 `StreamingMarkdownFilter`，只保留微信客户端能渲染的语法、剥离其余语法：

- 官方插件源码：`@tencent-weixin/openclaw-weixin@2.4.10` 的 `dist/src/messaging/markdown-filter.js`
  （ClawBridge 已按相同语义移植到 `server/src/shared/wechat-markdown.js` 与 `web/assets/lib/wechat-markdown.js`）。
- 微信 ClawBot 已适配 Markdown 渲染（标题、列表、代码块、表格、引用、粗体等）：
  [BlockBeats 报道](https://en.theblockbeats.news/flash/341273)。
- 逆向实现的协议 SDK 也记录了微信渲染范围（代码块/行内代码/表格/粗体/英文斜体/水平线等）：
  [weixin-ilink](https://github.com/zongrongjin/weixin-ilink)。

## 2. 兼容矩阵

| 语法 | 微信是否渲染 | ClawBridge 发送前处理 | 后台预览表现 |
| --- | --- | --- | --- |
| `#` ~ `####` 标题（H1–H4） | ✅ | 原样保留 | 标题样式 |
| `#####` / `######`（H5/H6） | ❌ | 去掉 `#####`/`######` 与空格，保留文字 | 普通文本 |
| `**粗体**` / `__粗体__` | ✅ | 原样保留 | 加粗 |
| `*斜体*` / `_斜体_`（中文内容） | ❌ | 去掉 `*`/`_` 标记，保留文字 | 普通文本 |
| `*italic*` / `_italic_`（非中文） | ✅ | 原样保留 | 斜体 |
| `***粗斜体***` / `___粗斜体___`（中文） | ❌ | 去掉标记，保留文字 | 普通文本 |
| `~~删除线~~` | ❌ 微信不渲染删除线 | 去掉 `~~` 标记、保留文字（`~~~` 围栏原样保留） | 普通文本（无删除线） |
| `` `行内代码` `` | ✅ | 原样保留 | 行内代码样式 |
| ` ``` ` 代码块（可标语言） | ✅ | 原样保留（块内 Markdown 不处理） | 代码块 |
| `| 表格 |` | ✅ | 原样保留 | 表格（支持对齐） |
| `---` / `***` / `___` 水平线 | ✅ | 原样保留 | 分隔线 |
| `> 引用` | ✅ | 原样保留（单行更可靠；多行可能被微信拆成多个引用块） | 引用块 |
| `-` / `1.` 列表（可缩进嵌套） | ✅ | 原样保留 | 列表（按缩进渲染层级） |
| `![alt]（url）` 图片 | ❌ | **整段移除** | 不显示 |
| `[文字]（url）` 链接 | ✅（按微信能力） | 原样保留 | 显示文字（预览不发起请求） |
| 裸 URL（`https://…`） | ✅ 自动识别为可点击链接 | 原样保留 | 链接样式 |
| `<https://…>` 尖括号 URL | ❌ 不识别 | 原样保留 | 按原文显示（含尖括号） |
| HTML 标签 | ❌ | 原样保留 | 按纯文本显示（安全） |

> 图片说明：微信文本消息不渲染 Markdown 图片。需要发图片请使用「发送消息」里的图片/附件能力（或 `v1` 媒体接口），
> 不要依赖 Markdown 图片语法。
>
> **换行与官方一致**：官方插件只做上表过滤、**不修改换行**；ClawBridge 现在同样原样保留模板换行
> （不再自动插入空行），模板里的排版换行不会变成消息里的空行。

## 3. ClawBridge 的实现位置

1. **发送前过滤**：`server/src/ilink.js` 的 `formatWeixinText()` 调用
   `filterWechatMarkdown()`（按微信渲染规则过滤），换行原样保留；所有文本发送（规则回复、定时通知、广播、v1 推送）都经过这里。
2. **后台预览**：`web/assets/admin/markdown-preview.js` 使用同一套过滤逻辑
   （`web/assets/lib/wechat-markdown.js`）后再渲染，因此预览 = 实际发送效果；弹窗会提示被微信规则处理的项
   （中文斜体数量 / H5-H6 数量 / 移除的图片数量）。
3. **模板预览**：`POST /api/admin/template-preview` 返回的 `replyText` 同样只做 Markdown 过滤，展示替换模板变量后的
   最终可发送文本；Markdown 预览不替换 `{{…}}` 变量。
4. **一致性保障**：`tests/unit/frontend-wechat-markdown-parity.test.js` 对服务端与前端过滤结果做固定样例 +
   随机组合的逐字节比对；`tests/e2e/app-rules.test.js` 校验真实发送文本等于过滤结果。

## 3.1 换行规则（与官方一致）

官方插件不修改文本换行，ClawBridge 也不在出站时自动增删空行：

| 场景 | 出站处理 |
| --- | --- |
| 普通文本相邻两行 | 原样保留单换行 |
| 空行分隔的段落 | 原样保留 |
| 列表项之间 | 原样保留 |
| 表格 / 代码块 | 原样保留 |
| 引用行 | 原样保留 |

> 说明：微信客户端如何渲染单换行由客户端决定；如果希望消息里出现明显的分段空行，请在模板里直接写空行。
> 模板渲染前会去掉「独占一行的 `{{#if}}` / `{{#each}}` / `{{else}}` / `{{/each}}` 块标签」带来的结构性换行，
> 避免条件/循环的代码排版在列表项之间输出多余空行；标签与文本同行的模板不受影响。

## 4. 模板写法建议

- 需要强调中文：用 `**加粗**`，不要用 `*中文斜体*`（会被去标记）。
- 需要小标题：用 H1–H4（`#` 到 `####`）；H5/H6 会被降级为普通文本。微信实际可能对 H1–H4 使用相近的标题样式，不要依赖字号层级。
- 需要图片：使用「发送消息」的图片/附件，不要写 `![…]（…）`（会被移除）。
- 需要链接：直接写裸 URL（微信自动识别可点击）；写 `<https://…>` 会按原文显示、不可点击。
- 表格、代码块、列表（含缩进嵌套）可放心使用；**引用单行更可靠，多行 `>` 可能被微信拆成多个引用块**。
- 普通文本单换行由微信客户端渲染；需要明确分段时写空行。
- **用户可控字段建议用 `{{escape 字段}}`**（姓名/备注等）防止值里的 Markdown 字符生效；URL、`{{response}}`、`{{raw}}` 不要转义。
